# 架构与按需注入规范

## 1. 架构策略：大体量、轻注入

- 大体量：知识库追求覆盖完整，截肢类型、辅具、题材各自独立成文件，允许总量持续扩充。
- 轻注入：任何时刻上下文里只保留当前任务必需的文件。常驻文件只有 `SKILL.md`；其余全部按需读取。
- 二者的平衡点是精细化分割：一个文件只回答一类问题，确保单次注入的体量小、指向准。

## 2. 分割粒度规则

1. 一个截肢平面一个文件（如「髋离断.md」不与「大腿截肢.md」合并）。
2. 一种辅具一个文件；跨辅具的流程性内容（如占手处理、连续账）单独成文件。
3. 一种题材一个文件；通用机制（豁免政策）独立成文件。
4. 单文件超过约 300 行时，优先按子主题拆分为新文件并在原位置留路由说明，而不是继续追加。
5. 事实数据与执行逻辑分离：机械检查规则存 `scripts/rules/*.json`，脚本只读规则不硬编码词条，维护规则不需要改代码。

## 3. 注入顺序：先大类后小类

1. 从 `SKILL.md` 路由树定位大类目录。
2. 先读该大类的索引/总表类文件（如 `02_生理事实/索引.md`、`03_辅具/索引.md`、`禁忌动作总表.md`）。
3. 再按索引指向读具体小类文件，只读与当前章节出场角色、当前场景相关的小类。
4. 读完即用，任务结束后不主动回灌已读内容；下一章需要时重新读取，避免跨章节的旧上下文污染。

## 4. 引用规则

- 文件之间需要互相指引时，给出相对路径与文件名，不复制对方正文，避免同一事实多处维护导致不一致。
- 单一事实只允许有一个权威出处：解剖事实以 `02_生理事实/` 为准，辅具操作以 `03_辅具/` 为准；其他文件只引用不重写。
- 发现重复表述时，按维护规范删除其中一处并改为路径指引。

## 5. 内容边界

本库服务于小说写作工艺与事实核查，不收录露骨性描写规范。亲密关系写作只覆盖情感推进、关系张力与身体事实准确性。
