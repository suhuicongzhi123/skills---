# 平台适配与降级声明（国内 agent 平台）

> 本文件说明本技能分层架构**在不同平台能开哪几层、哪层退化、退化后哪些保证作废**
> 宿主 hook 的平台中立规范在 `host-hooks.yaml`，转变工具 `scripts/install-host-hooks.py`
> ——国内平台安装技能后**须先注册 hook**（`.claude/` 会被安装器忽略），见「Claude Code（参照实现）」节。
> 能力位与分层开关以**本文件第 2 节为唯一权威**（重复的机器可读副本已删除，
> 消除双副本漂移；脚本与 hook 均不依赖该文件）。
> 原则：**任何降级都必须显式声明**。静默降级比明确不支持更危险——
> 报告外观不变、机检照样 PASS，但保证已经没了。

## 0. 先做合规前置验证（国内平台必做，优先于任何技术优化）

本技能含成人向题材与 B/C 档亲密尺度编排，国内平台普遍有前置/后置内容审核。
用一章典型设定在目标平台实跑，确认三件事：

1. 不拒答；
2. 输出**未被静默改写**（生理事实、尺度档、硬闸相关表述有没有被平台悄悄调整）；
3. `rules/hard-layer.md` 本身可正常注入。

静默改写尤其危险：账本字段齐全、机检全绿，但正文已经不是按本技能写的了。
验证不通过的平台，**不进入后续架构评估**。

## 1. 内核（平台无关，永远可开）

| 文件 | 作用 |
|---|---|
| `rules/rules.yaml` | 规则 IR，口径与约束的唯一事实源 |
| `rules/hard-layer.md` | 硬约束常驻层，纯文本约 4 KB |
| `templates/chapter-contract.md` | 本章规则包骨架 |
| `core/prose-craft.md` | 成文工艺总线（章节因果链／叙事距离／氛围／跨章文风一致性／正向闸）；**按需层**，不常驻 |
| `core/short-form.md` | 短篇与单章缩放唯一权威页（≤10 章）；**按需层**，其余文件只留指针 |
| `eval/eval-set.yaml` + `scripts/optimize_prompts.py` | 离线回归集与优化（产物是普通文本，跨平台最好） |

**最低要求**：能读到这些文件。纯对话平台若连文件都读不了，由宿主把
`rules.yaml` + `hard-layer.md` 直接贴进对话。
`scripts/compile_rules.py` 的编译结果可先在外部 CI 跑好，把 PASS/FAIL 贴进来——
这一层**完全不依赖 agent 愿不愿意执行**，是全平台最硬的保证。

## 2. 增强层开关

| 层 | 需要的能力 | 关闭 / 降级后**失去**什么 |
|---|---|---|
| L0 内核（纯数据 + 离线编译结果） | 无 | 最基础口径保障，任何平台都应保留；无可降级项 |
| L1 规则展开 | shell 或 MCP 或宿主 prompt 注入 | 规则包改由人工拼，scope 漏项不再被脚本检出 |
| L2 编译检查 | 能跑 python | 枚举冲突、编号重复、边界差一档只能靠人工逐字校对 |
| L3 状态机 + 校验回路 | 能跑 python | 状态机退化为 advisory，**跳步不再被强制拦截** |
| L3b hook 强制 | 生命周期 hooks | **硬层常驻保证失效**——压缩或长会话后可能被驱逐 |
| L4 结构化保证 | 原生 JSON Schema 严格输出 | 格式由硬保证降为软保证（「格式合法 ≠ 内容合规」是恒定边界，非本层失去项） |
| L4b 受限解码 | logits / 自建推理栈 | 国内托管 API 基本不可得，**默认关闭** |
| L5 独立红队 | 真独立上下文子代理 | **独立性声明作废**，质量等级降为「自审」 |
| L6 离线优化 | 无（离线） | DSPy 自动优化为预留接口；当前只输出静态评分并显式声明，不假装优化 |

### 三条最危险的静默降级

1. **冷读独立性失效**：不支持真子代理时，用同会话换角色顶替。报告外观与真冷读一致，
   实为自审，恰好摧毁 `core/workflow.md` 的 pro/max 输入隔离设计。
   → 必须在账本 `工作流执行日志` 写明「独立性声明作废」，且报告里不得保留「独立冷读」字样。
2. **硬层被驱逐**：压缩后只重挂最近一次 Skill 调用的前 5000 tokens，早先调用会被整个丢弃。
   → 有 hooks 走 hook 强制重注入；无 hooks 由宿主每次拼 system prompt；
   至少做到**每章开写前重读** `rules/hard-layer.md`。
3. **注入索引不触发**：多数国内平台用 Rules / 知识库自动加载，不等于 Agent Skills 的渐进披露。
   → 可能出现「只把 `SKILL.md` 当普通规则读了，其余文件从未加载」。
   → 对策：本章规则包（`query_rules.py --format text`）是**单份文本**，直接注入，不依赖索引命中。

## 3. 平台档位（公开资料整理，非实测；须按实际版本复测）

- **能力较全**：WorkBuddy、CodeBuddy、Kimi Code、Qoder CN —— 可开 L0–L3b、L5 与常驻的 L6（L4 视厂商实现、L4b 多数仍不可得）。
  注意：各家 hook 事件集合、子代理隔离语义**不互通**，配置不能直接搬。
- **部分能力**：TRAE、文心快码 Comate、CodeGeeX 本地部署 —— 有 shell、hooks 不完整或无真子代理。
  CodeGeeX 私有化是少数可能自建推理栈、拿到 logits 的形态。
- **仅内核**：纯对话/云智能体平台 —— 无本地文件与脚本，只能跑 L0 + L6 结果。

### Claude Code（参照实现）

- 仓库根 `.claude/` 接入层 clone 即得：`settings.json`（SessionStart hook 强制注入
  `rules/hard-layer.md` 全文＝L3b 硬层常驻宿主强制）＋ 三个 skill——
  `chapter-rules`（L1 规则包展开＋`!` 动态注入硬层）、`redteam-review`
  （`context: fork` 独立子代理红队＝L5）、`verify`（交付闸四链，命名 `verify` 挂
  commit 前自动运行约定）。
- 可开层：L0–L5 与 L6 全开（L4 视 API 侧实现，L4b 无 logits 访问除外）。
- ⚠ hook 事件集与 fork 语义是 Claude Code 专有扩展（非 Agent Skills 开放标准部分），
  **其他平台不可直接搬 `.claude/` 配置**——用 `scripts/install-host-hooks.py` 转变
  （事件钩子型→等价注册；规则常驻型→规则文件＋强制力降级显式声明；未核实→不猜测写入，
  见 `host-hooks.yaml`），或按本文件第 4 节适配自检逐项重建。
- 写作项目独立建仓时：复制 `.claude/` 与 `novel-amputee-writing/` 到项目根，
  `${CLAUDE_PROJECT_DIR}` 相对路径即成立。

## 4. 每章开写前的适配自检

- [ ] 已确认目标平台档位，并把启用的层写入账本 `工作流执行日志`
- [ ] 每一层降级都已**显式声明**对应失效的保证
- [ ] `rules/hard-layer.md` 已整段注入（不是摘要、不参与检索）
- [ ] 本章规则包由 `scripts/query_rules.py` 生成，或人工按 `templates/chapter-contract.md` 核对 scope
- [ ] 编译检查结果已读（PASS 或已处理的 FAIL 清单）
- [ ] 合规前置验证已通过（第 0 步）

## 5. 语义层不在任何平台的机器保证范围内

`templates/ledger-schema.json`、`gatecheck`、状态机、编译检查——这些只保证
**可形式化**的项。下列必须靠硬层常驻 + 冷读 + 人工逐字校对：

- 生理事实语义（髋离断 / 膝上 / 膝下 / 上肢差异，**❌ 不跨类型套用**）
- 文笔、声口、去 AI 化、心动句非同源
- `eval/eval-set.yaml` 里 28 条历史复发模式（其中**评测用例 L3** 语义层 13 条；注意与能力层 L3 同名不同义）

**机检全绿 ≠ 内容无误。** 这一条在任何平台都成立。
## 6. 上下文预算表（小上下文机型选档）

> **实测口径**：硬层 4.3K 单独整段注入；规则包 text 5.9K／compact 3.7K
> （已用 `scripts/query_rules.py --no-hard-layer` 去掉**重复附带**的硬层全文）；
> 章契约 3K＋账本 1K ⇒ 写作时点在场视图 **≈14K**（32K 档 ≈12K）。
> **默认规则包仍附硬层全文**（text 10.1K／compact 7.9K），专供「宿主只拼这一份规则包」
> 的无 shell 平台；那种情形硬层只出现一次，❌ 不得再与单独注入叠加。
> 注入索引是收集/规划阶段工具，**写作时点不回读**（见 workflow 第 8 节第 7 条）。
> 压缩发生时按 `core/workflow.md#压缩恢复协议` 重读最小恢复集（约 14K，不重建全量）。

| 机型上下文 | 推荐配置 | 分配与红线 |
|---|---|---|
| **32K 档** | compact 规则包＋`--no-hard-layer`＋flash 单轮直出＋lite 自查（短篇适用） | 硬层＋compact＋契约 ≈12K 常驻；草稿写作 ~10K；审查 ~4K；余量对话。**红线**：禁 pro/max（审查报告放不下）；每场景增量落盘必开 |
| **64K 档** | text 规则包＋flash/pro | ≈14K 常驻＋完整自查（38 项）＋上一章全文在场；pro 冷读可开（报告独立子代理上下文另计） |
| **128K+ 档** | 全配置（pro/max） | ≈14K 常驻＋大纲与人物卡常驻＋max 四角色产物链；无特殊约束 |

- 压缩频发机型（第一章成文前压缩 ≥1 次）：**必开**压缩恢复协议＋增量落盘；
  连续两章触发恢复＝切 compact 档并考虑降级 pro→flash（降级须显式声明）。
- 短篇（2–10 章）任何机型都可走 lite 档（5 题收集＋10 项自查）——
  交付闸机检不降级，降的只是收集与自查成本。
