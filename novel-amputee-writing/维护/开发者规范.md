# 开发者规范（维护宪法）

> 本文件只服务技能库维护，不进创作注入链。
> v19.14.0 起生效。旧版本中的绝对禁令、配额和维护偏好不再自动继承，冲突时以事实、故事质量与实际验收为准。

## 一、库定位与最高原则

- **库定位**：面向慕残者（devotee/wannabe）群体的截肢者题材小说写作地基。规则与素材按需取用，库里有不等于本书要写。
- **故事优先**：先人物目标、冲突、关系与独特条件，再选截肢类型和受众元素。
- **事实优先**：受众偏好不能改写生理与物理；常见情况不能升级为类型定律，个体情况不能升级为全体能力。
- **三条维护原则**：
  1. **维护单一来源，运行时自包含**：同一规则只在一处定义，写作时按本章生成足够完整的小节，不让模型追多处指针才能行动。
  2. **写作与审查分离**：写作侧提供判断与素材，审查侧提供验证；基础层与题材规则可共享。
  3. **质量优先于增减**：删除错误、重复和伪精确，补充缺失的必要条件。禁止以“只减不增”阻止必要修正，也不以“补充”制造新官僚规则。

## 三、注入与事实分层

- **常驻只有 SKILL.md**，其他文件按阶段和场景读取，不整体加载。
- **权威源直读**：默认由写作员读取设定、在场角色卡、章级任务单和原始库小节，不强制生成书级创作包。长项目确需缓存时才生成可选薄底稿，只存跨章硬事实与索引，不复制声口、技法、受众理论或动态状态。
- **事实分层**：
  - 解剖与物理：缺失肢体不可凭空完成，虚构豁免须登记。
  - 常见配置：只能作为默认起点，不得写成绝对。
  - 个体变量：装备、训练、皮肤、健康、年龄、环境和个人选择。
  - 审美偏好：只决定选材与呈现，不冒充事实。
  - 叙事许可：不同题材、视角和文体可选择，不设“好小说唯一结构”。
- **题材增量**：现实向无超自然；幻想与末世异能使用同一登记原则，不让题材隔离造成能力无来源。
- **条件注入**：A 档禁读成人目录；B/C 档只读相应露骨程度与专项内容，普通照护不自动触发。

## 四、格式铁则

1. 编码 UTF-8 无 BOM，换行 LF。
2. `SKILL.md`、维护脚本与配置用英文名，其余文件与文件夹用中文。
3. 标题层级：`#` 全文一次；`##` 用中文数字；`###` 用 `x.y`，x 为所属 `##` 序数。调度链节点名（S0／S1／S3／S4／S5）、协作代理中的短功能标题（如「关键交锋」）以及 `审查层/审查总纲.md` 第二节下的九个维度标题（`1. ...` 至 `9. ...`）可作例外，不必改成 `2.1` 这类形式。大改版可重排，但必须同步全库引用。
4. 超过 100 行的子目录正文文件与 `SKILL.md`，顶部加目录块：`> **目录（按需读取，勿整体加载）**：…`。`维护/` 文档豁免本条，也不纳入 SG-5。
5. 规则正文优先写适用条件、判断与例外，少用没有边界的“必须／绝不”。
6. 反例须带「禁止／❌／反例／不写」之一，防止模型把反例当正例。
7. 示例抽象化，不带可识别的真实作品、人物或真实稿件专名；例句只示范机制，不作模板。
8. 跨文件引用用库相对路径＋锚点；删除或改号后同步全库，禁止悬空指针。
9. 每次修改后清理描述旧行为的注释、目录、优先级和审查规则，不只改正文。

### 类型文件结构闸门

新类型文件须覆盖：形态（下肢可用「残肢形态与承重」）、运动能力（下肢可用「移动方式」覆盖）、体位与动态、日常动作差异、身体细节、幻肢感、服装、不可能动作、受限清单。拐杖或假肢使用差异在该类型会触发时必写；上肢在拐杖默认不触发时可以不单列独立节，但须在适用边界写清。双侧叠加按叠加层结构，不套单侧必填节。节序可按类型调整，不要为凑节名空增重复节。写作要点为选填。

## 五、编号与素材

- 素材字母沿用：A 行动、O 职业、P 性格、R 关系、M 心理、L 情节、F 恋物、S 性爱、B SM、G 器官、E 表情、D 台词、K 现实感、N 命名、W W视角。
- 截肢类型直接用文件名，不用字母替代。
- 编号追加不复用、不重排，删除后空洞合法；MAJOR 若必须重排，须更新所有引用并在变更记录说明。
- 审查级别固定为 R0/R1/R2，避免与亲密 A/B/C 混淆。
- 不复活已废弃的 IR、指纹、印章和复杂状态机，除非用户明确提出新的可验证需求。

## 六、尺寸闸门

单一事实源＝`维护/size_gate.json`，执行＝`python 维护/size_gate.py`。

| 项 | 上限 |
|---|---|
| SKILL.md | 25 KB（25600 B） |
| 基础层 单文件 | 64 KB（65536 B） |
| 写作层/成人内容 单文件 | 60 KB（61440 B） |
| 题材层 单文件 | 55 KB（56320 B） |
| 审查层 单文件 | 30 KB（30720 B） |
| 协作代理/模板层 单文件 | 12 KB（12288 B） |
| 全库合计（不含维护） | 1250 KB（1250000 B） |

- 超限优先删重复、错误和无效素材，不靠删掉必要条件压线。
- 闸门只测体积、编码和目录块，不测事实、逻辑、人物和剧情质量。`SKILL.md` 纳入 SG-1、SG-4 与 SG-5；`维护/` 仍豁免体积合计与目录检查。行数按 `splitlines()` 计算。
- 体量下降不是目标本身，目标是以更少但更有效的规则提高成文质量。

## 七、版本与改动流程

### 7.1 SemVer

- **MAJOR**：目录结构、路由、工作流、事实基准或不兼容规则变化。
- **MINOR**：向后兼容的新类型、新题材、新模块和实质素材。
- **PATCH**：事实纠错、冗余删除、指针修复和示例替换。

版本号只记 `SKILL.md` frontmatter 的 `version`，`维护/CHANGELOG.md` 倒序记录，17.0.1 及以前归档于 `维护/CHANGELOG-归档.md`。一次维护只升一次，按最高级别；用户明确要求未发布期间保持版本时，不擅自升号，改用可选薄底稿内容基线区分维护批次，正式发版再确定版本级别。

### 7.2 改动流程

1. **确认基线**：库已纳入 Git 时检查 diff 与状态，保留用户其他未跟踪文件，不擅自提交、还原或拉取。
2. **分阶段修改**：先事实安全，再写作人物，再战斗题材成人，再工作流与维护，最后验收，避免大范围修改失去重点。
3. **查引用与冲突**：检索删除、改名和旧口径，更新全库相关位置。
4. **跑闸门**：`python 维护/size_gate.py`，超限先处理。
5. **实际验收**：执行引用、机检、场景和跨章检查，不能只跑体积。
6. **登记**：更新 CHANGELOG 与版本，列清推翻内容、保留内容和未验证边界。

## 八、验收要求

每次大改至少覆盖：

- **结构**：引用无悬空、数字小节锚点无错配、UTF-8/LF、`git diff --check`。
- **脚本**：真实执行确定性检查，含对白、医疗、合法情绪、危险搬运、错误文件与跨章自然排序。
- **场景**：单侧下肢无轮椅、双侧装备、肩离断外部动力、恢复与亲密、危险搬运、合作对话、敌人重复有效策略、维修替换、成年与授权。
- **本次回归**：慕残向无性与无露骨仍有看点；高潮战有主动行动与战果确认；健侧能力不被误删；起坐先建立支点；双拐横拦不直接踢唯一健腿；多辅具出门有必要性与容量依据；单腿跳区分会／稳／敢／值。
- **流程回归**：默认无创作包也能由权威源完成短篇与长篇任务；长项目可选薄底稿不存动态、不覆盖来源。S0 按 S0a（追问期轻载）与 S0b（靶向建档，已定类型跳过选型表）分层加载，并完成静态看点→主线因果锚定。S1 规划可按批连排骨架，但 S3 起草与 S4 R1 章审必须逐章串行接棒（废除跨章并行起草），续章必读上一章 4 项结构化实际末状态快照（含辅具衣物位置与已用看点／窗口指纹）。S3 强制执行 `Write 初稿落盘 → Edit 定点精修与零解释终检` 两步工具链。S4 设 Pre-R1 预拦截快修闸、保活气反过度审查护栏、靶向手术式 REWRITE（划定保留区与手术区）与 2 轮熔断；批次 R2 与 S5 全书复核前置运行 `确定性检查.py --cross`。S1、S3、R1／R2 与全书语义复核必须有真实子代理调用和交付记录，主对话不得静默接管；失败时暂停，降级须另有用户明确授权且不能冒充标准流程通过。
- **二次审查回归**：虚构豁免只在登记范围内生效；R1 回原始事实源；AI 登记的项目承诺同样验收；可选薄底稿按版本与内容基线识别；无辅具不凭空取装备，新角色可建初始能力；先天瘢痕与幻肢分开；动力踝不被普通假脚误伤；末世不强制失效／无伤代价；A 档不读成人目录；脚本与项目路径分别解析。
- **服装结构回归**：类型文件与路由中的“见／另读”必须实际读取；裤装取 6.1–6.3，裙装另读 6.4；裙摆不套裤管挽结、塞起或残端下封口；裙裤、外裙里裤与连身款按实际结构分层。
- **薄流程与受众回归**：短项目不生成创作包，长项目仅在原始资料超出有效上下文时生成薄底稿；章纲不预写完美情绪台词，关键对话按意图／需要、顾忌、回应及策略／关系／行动变化规划，谈判再写要价与交换。初稿后选一场关键对话／对抗做局部第二遍成文，不全章换词、不强造冲突。项目主导体验与条件触发仍按原规则；R2 覆盖与独立复审要求不变。
- **显著性与成文闭环回归**：缺失与辅具可直接承担描述、辨认和侦查功能，不写全员必然最先注意；同一事实多层重申与跨章同镜头须看原文，有效母题和持续审美复现不误删。承诺区分持续／阶段／单次兑现与触发条件，单次兑现后归档；候选钩子与重大改向分开。命中声口／复读时给连续原文，按根因回改而非只改最新章；R1／R2 通过不冒充 S5 合并完成，未命中不增加表格或试音任务。

## 九、常见维护坑

- **两处副本漂移**：同一规则多处复制，修一处忘另一处；应使用单一来源与派生摘要。
- **只修关键词**：把“AI 味”当词表问题，忽略事件、人物和结构。
- **补丁套补丁**：在旧错误旁不断加注释，制造新的优先级冲突；错就改原文。
- **硬指标诱导**：配额最容易被性价比模型刷满，同时杀死自然表达；除事实安全外优先给判断。
- **示范句成为指纹**：优先给条件、判据和反例，不让整句台词和动作成为跨书模板。
- **派生摘要覆盖来源／薄底稿存动态**：二手摘要可能放大转述错误；动态状态写入薄底稿会让后续章节读到旧装备、知识和关系，必须回权威源并分离状态。
- **未验证宣称**：体积闸门通过不代表优秀作品，静态审查通过也不代表目标模型生成已验证。
