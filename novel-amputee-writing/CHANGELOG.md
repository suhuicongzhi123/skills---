## [7.0.0] - 2026-11-09 · 超大体量技能库重组（效率／稳定性／创作性价比）

- **性质**：MAJOR（6.3.0 → 7.0.0）。动因：联网检索超大体量技能库优化方案后，
  对本库做针对性重组——允许重组、旧内容让位新内容、删除旧内容缩减体积、
  脚本允许修改且哈希可重算；**生理事实专项内容不删减、不修改**（本轮仅做分支索引分组，
  未移动或改写 `types/` `topics/` 与 `core/physio-audit.md` 任一字节）。

### 一、检索结论（2025–2026）

- Agent Skills 官方最佳实践：**SKILL.md body ≤500 行**、引用保持**一级深**、
  长参考文件（>100 行）**顶部带目录**（防只取前 N 行读不全）、元数据一行一技能、
  详细规则进 references/ 按需加载。
- 上下文工程：context rot（Chroma 2025，18 模型）与 lost-in-the-middle（Liu et al.）
  证明**长上下文不是注意力**；关键约束放首/尾，稳定前缀利于 prompt caching；
  每轮重复注入同一段文本＝纯税。
- Skill 失效四型：**Duplication**（同义多副本）／**Sediment**（旧方案沉积）／
  **Sprawl**（整体蔓延）／**No-op**（无行为增量）；修剪法＝Relevance＋No-op＋Deletion Test、
  合并重复段落为表、散文转表格、删冗长反模式示例、单一事实源。
- 压缩实证（Caveman Prompt Compression）：50–77% token 削减，成本 -34%、时长 -27%、
  质量 +17%——噪声减少、表格无歧义、单一事实源消除互相冲突的副本。

### 六、人工通检记录

**通检方式**：逐字通读所有被修改文件的最终磁盘版本（`SKILL.md` 396 行全文、
5 个大文件的顶部目录、4 个脚本的改动段、`rules/rules.yaml`、`core/workflow.md` 第 8 节、
`PLATFORM-CN.md` 预算表、`templates/chapter-contract.md` 头部、`eval-set.yaml` 改动用例、
`CHANGELOG.md` 全文），并与 v6.3.0 备份逐字比对删除/改写段落；
机检（verify.py / quick_validate / YAML 解析 / AST）**仅作辅助定位，不作结论**。

**机检全绿时仍存在、由人工发现并修复的 15 类问题**：

1. 注入索引把带 `#锚点` 的引用写进 YAML 内联数组 → 锚点解析器吃进逗号/`]`，产生 63 处假「锚点落空」。改为逐行列表，并把格式禁令写进 〇-规。
2. 规范条款的反例写成带后缀的占位文件名 → 被当成真实引用，报 2 处假「悬空引用」。改为不带后缀的占位写法。
3. `SKILL.md` 严重错误第 6 类「不得编辑 gatecheck.py」与本轮「脚本可改、哈希可重算」授权冲突 → 明确限定为**创作执行期间的 AI 代理**，新增维护期例外与重算流程。
4. `core/prose-craft.md` 旧声明「gatecheck.py 与哈希基线不动」未同步 → 改为「内容未改、基线迁至 rules.yaml 可重算」。
5. `query_rules.py` docstring 把默认形态写反（说成「硬层全文可选」）→ 改为「默认仍附全文，仅 --no-hard-layer 可去」。
6. `verify.py` FAIL 时只打印子进程尾 6 行，会掩盖首行「[1] 锚点落空 N」明细 → 改为 FAIL 打印全量输出。
7. `core/workflow.md` compact 旧口径「硬层 4.3 KB 全文永远附带不可减」与本轮改动互斥 → 改为可叠加 --no-hard-layer 的实测口径。
8. `/verify`（仓库根 slash command）与新 `scripts/verify.py` 同名未区分 → 在 workflow 注明两者职责不同、勿混用。
9. `templates/chapter-contract.md` 生成命令未带 --no-hard-layer，与 workflow 第 8 节第 4 步不一致 → 统一带参数并写明「未注入硬层者须去掉」。
10. CHANGELOG 与 PLATFORM-CN 的体积数字为改前估算或占位 → 全部按实测回填。
11. `SKILL.md` 两处标题带旧版本号、`rules.yaml` 头部带 v5.24.0 → 去沉积标注。
12. 「改完两条 PASS」表述含混（verify 内含两条命令、另有 quick_validate）→ 改为「两个校验器都 PASS」，并补 --update-baseline 入口。
13. 注入索引里另两处带锚点的内联数组违反新定的索引格式规则 → 改逐行。
14. `SKILL.md` 文件结构表未列 verify.py、三层披露表述与实际内容不符 → 补齐。
15. CHANGELOG 的旧版引用数、体积换算、「文档已区分」等不实表述 → 按实测与落实结果校正。

**生理事实专项核验**：`types/*.md`（7 个）、`topics/*.md`（18 个）、`core/physio-audit.md`
改前/改后 SHA-256 聚合摘要一致（`ef3bab31…c8ed`）；另逐字抽查
`types/hip-disarticulation.md`、`topics/combat-mechanics.md`、`core/physio-audit.md` 首段，
**零删减、零改写**，符合「可重组但不删减和修改已有内容」约束。

**另核对（非错误，有意保留）**：`host-hooks.yaml` 的 `chapter-rules-expand` 命令保留
**默认含硬层全文**形态，以兼容无 SessionStart 硬层 hook 的平台；
与 `core/workflow.md`／`templates/chapter-contract.md` 的 `--no-hard-layer` 形态构成
**条件化差异**，`note` 字段已写明何时可加参数，不构成口径冲突。

**结论**：人工通检通过。机检只能验锚点、枚举、格式与字段；上述 15 类均为语义、
口径与跨文件一致性问题，第 1、2 项更是**机检自身误报**——印证机检不可替代人工逐字校对。
