## [6.2.1] - 2026-11-08 · 账目隐喻格言禁令（用户实测点名句式）

- **性质**：PATCH（6.2.0 → 6.2.1）。动因：用户实测点名「这是他的账，让他自己平。」
  及其衍生句式（「这是你的账」「这是我的账」「自己的账自己平/算/还」等），要求立禁令。
- **禁因三重**：①AI 高频格言式收束套路（冷峻账目腔，看似深沉实为套话，与「去总结套话」
  「勿坍塌歧义」同族）；②**本题材特有危害**——把她的身体/受限写成「一笔要摆平的债」，
  暗合补偿叙事与苦难叙事（残缺≠亏欠，没有「平」的义务）；③格言收束替角色下判断、
  替读者做总结。
- **落点**（`core/style.md` 去AI化节）：新增「去账目隐喻格言」条目＋改写对照两则
  （❌「这是他的账，让他自己平。」→ ✅ 停在她的具体反应「她把那张纸对折，塞进了
  抽屉最里头」；❌「这是你的账，你自己平。」→ ✅「这话她没接。锅里的水开了，
  她先去关火」）；「章节结尾」禁句式列表补「这是X的账，让X自己平」。
- **合法边界**：末世/生存题材的**真实物资账目情节**（记账场景）不受影响——禁的是
  人格/关系/责任/身体的账目隐喻收束，不是记账本身。
- **联动四件**：selfcheck DEAD 词表补 7 项（的账，让他/她/你/我自己平＋的账自己
  平/算/还——均带「账」与收束动词，真账目句式不命中；禁令句人工确认档）；
  `templates/chapter.md` S41 点名；`eval/eval-set.yaml` 补 E-019（真实用户反馈问题
  沉淀，L1）；版本五处 6.2.1。
- **哈希基线不变**：gatecheck.py 未动（账目句式有真账目合法边界，放 DEAD 人工确认
  档而非 [18] 强 FAIL——强 FAIL 适合零容忍项），`182bbd8191aa0e5e` 沿用。
- **归档**：[5.22.0] 压为单行摘要移入历史归档区（维持近 6 版全文）。

## [6.2.0] - 2026-11-08 · 小上下文适配（压缩恢复/自查分级/单轮直出/lite 档/compact 规则包）

- **性质**：MINOR（6.1.0 → 6.2.0）。动因：技能体量庞大——**小上下文模型在第一章
  成文前很可能压缩一次甚至多次**；同时按维护者决策落盘降本提速方案
  （「流程提速（pro 并行化）」一项**不采纳**，其余全部采纳）。

### 一、压缩恢复协议（P0 · 多轮压缩的正面解）

- 根因定位：压缩丢的不是「状态」（账本/草稿/报告已落盘），是「注入」——硬层/规则包/
  章契约/人物细节活在上下文里，摘要最爱丢禁令细节。
- **协议三步**（`core/workflow.md#压缩恢复协议`＋`SKILL.md#〇-压`）：①触发自检——
  每次接到写作/续写指令时问「能引用 hard-layer 禁令原文吗」，不能＝疑似被压缩；
  ②最小恢复集 5 件（硬层 4.3K＋规则包 8.6K＋章契约 3K＋账本坐标块＋上章末 500 字，
  合计约 16 KB，按序重读，❌ 不重建全量）；③恢复后核对＋**恢复留痕**（记一行账本日志
  ——压缩发生是可审计事件；连续两章触发＝提示切 compact 档）。
- **宿主 hook 联动**：`host-hooks.yaml` hard-layer-inject 增 `pre_compact` 事件
  （Claude Code PreCompact——压缩前把恢复协议引导写入摘要）；规则常驻型平台
  生成物（install-host-hooks.py）同步含恢复协议条款。
- **堵两个落盘缺口**：①**章契约落盘**——填好的契约存项目目录 `chapter-contract-N.md`
  （压缩丢计划风险归零）；②**正文增量落盘**——每写完一个场景/节立即追加进章草稿文件，
  压缩最多丢「当前片段未落盘尾部」，重写代价从整章降到一段。

### 二、自查分级 49 → 38 语义项 ＋ gatecheck [18] 机检 11 项（P1 · 审查降本）

## [6.1.0] - 2026-11-08 · 宿主 hook 平台兼容层（host-hooks 规范＋安装转变器）

- **性质**：MINOR（6.0.0 → 6.1.0）。动因：`.claude/` 只被 Claude Code 识别，
  **国内 agent 平台安装技能时会自动忽略该目录**——宿主 hook 需要兼容性处理，
  使平台安装时能转变成自身可用的形式。
- 设计：hook **语义与平台形态分离**——单一事实源 `host-hooks.yaml`（平台中立规范），
  `.claude/` 只是它在 Claude Code 上的原生形态；安装到其他平台由转变器生成对应形态。

### 一、新增 `host-hooks.yaml`（平台中立规范，技能包根）

- 四条 hook 语义（与 `.claude/` 接入层一一对应）：hard-layer-inject（硬层注入，
  session_start＋before_chapter_write，整段禁裁剪）／chapter-rules-expand（规则包展开）／
  verify-gate（交付闸四链，before_commit／before_deliver）／redteam-review（独立红队，
  pro/max 章末）——每条含 events/action/强制等级/降级声明。
- 转变规则三分：**事件钩子型**（宿主强制）→ 等价注册；**规则常驻型**（多数国内平台，
  无事件钩子有规则常驻机制）→ 规则文件注入＋**强制力降级显式声明**
  （宿主强制 → 规则常驻＋AI 自律）；**未核实平台** → 不猜测写入，输出人工注册指引。
- 平台注册表：claude-code（verified: true）＋ codebuddy/trae/qoder/kimi-code
  （verified: false，目录形态按公开资料，注册前须按平台文档核对）＋ generic。

## [6.0.0] - 2026-11-08 · 宿主级接入层（Claude Code 参照实现）＋ 三处实测 bug 修复

- **性质**：主版本号升级（5.24.0 → 6.0.0）。动因有二：
  ① v5.6.1 回退时的结论「绝对强制需宿主级 hook，超出技能包能力」**首次落地为随仓库分发的接入层**；

### 一、三处 bug 修复（均隔离单元测试 / Windows 实测实证）

1. **P0 · gatecheck [17] 跨章轨迹误卡（长篇第 2 章起无法过闸）**
   - 根因：`state_machine.py --advance` 产生**跨章累计轨迹**（「已交付 → 待规划」回卷即其设计），
     而 [17] 闭环判定假设轨迹是**本章**的——第 2 章起轨迹必含历史章「已过闸」，中间态跑交付闸
     必误报「已过闸却未闭合」。v5.24.0 的六分支回归用例为单章轨迹，未覆盖累计场景。
   - 修复：闭环判定改看**当前章段**＝轨迹中最后一次「已交付 → 待规划」回卷点之后的段；
     历史章的「已过闸」不再构成当前章的闭环义务，单章行为不变。六分支回归全过：
     跨章中间态（原误卡）→ PASS ／ 跨章完整闭环 → PASS ／ 跨章早期 → PASS ／
     单章已过闸未交付 → 拦 ／ 单章 pro 伪跳冷读交付 → 拦 ／ 跨章 pro 已过闸未交付 → 拦（缺冷读）。
2. **P1 · validate_output.py Windows 中文系统不可用**
   - 根因：`subprocess.run(text=True)` 未指定 encoding——Windows GBK locale 解码子进程
     UTF-8 输出抛 `UnicodeDecodeError`（读线程崩溃、四项子检查结果全丢、`--json` 输出损坏）。
     v5.24.0 的测试环境非 Windows，未暴露。
   - 修复：`encoding="utf-8"` ＋ `errors="replace"` ＋ 环境变量 `PYTHONIOENCODING=utf-8`
     强制子进程用 UTF-8 写管道，两侧对齐。Windows 实测 `--json` 正常解析、子检查明细完整。
3. **P2 · state_machine.py 重写账本丢注释**
   - 根因：`--advance` 落盘用 `yaml.safe_dump` 全量重写——账本行内注释与手写格式
     **全部丢失**（实测顶部注释被删）、缩进漂移。
   - 修复：新增 `patch_ledger()` **文本级推进**——定位「章节状态」块，只替换
     当前态／轨迹两行的值（保持原缩进），其余逐字保留；缺字段按块内缩进追加；
     账本无「章节状态」块时 FAIL 提示按模板补块（不再静默整块创建）。实测：顶部注释、
     块前注释、当前章字段、其余块全部原样保留。

### 二、宿主级接入层（仓库根 `.claude/` · Claude Code 参照实现）

- **`.claude/settings.json`**：SessionStart hook 强制注入 `rules/hard-layer.md` 全文
  （L3b 硬层常驻从「AI 自觉重读」变宿主强制，封死「硬层被驱逐」静默降级）。
- **`.claude/skills/verify/`**：交付闸入口——selfcheck → compile_rules → state_machine →
  gatecheck 四链全跑，任一 FAIL 即不得交付／commit；命名 `verify` 挂 commit 前自动运行约定
  （Claude Code v2.1.286+ 会话）。
- **`.claude/skills/redteam-review/`**：红队验证 skill，`context: fork` 独立子代理上下文
  （L5 独立性由宿主保证；输入隔离、禁止自证「自查未发现」、全过也须 ≥3 段反证轮）。
- **`.claude/skills/chapter-rules/`**：本章规则包展开 skill——`!` 动态注入硬层
  （skill 激活即宿主预执行，AI 无法跳过）＋ 按账本坐标跑 `query_rules.py`。
- 分层映射：L1＝chapter-rules ／ L3b＝SessionStart 注入 ／ L5＝redteam-review fork ／
  交付闸＝verify。Claude Code 上可开 L0–L5 与 L6（L4b 无 logits 访问除外）。
- 接入层位于技能目录（`novel-amputee-writing/`）之外，selfcheck 扫描范围不受影响；
  其 hook 事件集与 fork 语义为 Claude Code 专有扩展（非 Agent Skills 开放标准部分），
