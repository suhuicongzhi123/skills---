# 每章剧情安排

> 类型无关。大纲阶段排布、每章开写前核对。
> 分工：`core/structure.md` 管弧线层级，`core/scene.md` 管场景内部，**本文件管章与章之间**。

## 一、章六要素（每章开写前必须填）

| 要素 | 内容 | 判据 |
|------|------|------|
| **本章 beat** | 推进所在弧线的哪一步 | 填不出 → 这章没有存在理由 |
| **本章 turn** | 章内哪个瞬间改变了什么 | 无 turn → 流水账 |
| **新信息** | 读者这章新知道了什么 | 全无新信息 → 砍或合并 |
| **stakes 变化** | 相对上一章升了，还是换了类 | 连续 3 章无变化 → 节奏 plateau |
| **章末钩子** | 停在什么上（见下） | 无钩子 → 断更风险 |
| **受限 beat** | 本章哪个受限场景（见下） | 每章 ≥1 核心受限（设计优先，见一-补）；无核心受限＝缺项，回大纲层补设计 |
| **本章阅读承诺** | 本章开头给读者的一个可期待的问题/目标：「这一章我想看到什么」 | 填不出 → 读者进章无目标感；**章末须回应**（兑现/翻转/推进，三选一，不可无回应） |
| **主冲突线 beat** | 本章对主冲突线的状态：推进 / 蓄势 / 留白 | 烈档：连续 3 章 ≥2 非留白且留白不连 2 章；高档：5 章 ≥3；中档：5 章 ≥2；低档：只登记（口径见一-补2） |

> **章首承诺＝入口拉力，章末钩子＝出口拉力**，互不替代：承诺让读者愿意进入本章，钩子把读者推去下一章。
> 承诺由本章剧情**内生**（通常＝本章 beat 的具体化），不排班；须**具体可判**（能不能赶上末班车），❌ 不写抽象承诺（「她会面对自己」）。
> 承诺可跨章延续：本章只推进不解决时，章末钩子即该承诺的延续态。
> 与 structure.md 的关系：本章承诺＝弧线 central question 的**局部投影**。

### turn 的三条生成路径

- **信息反转**：新事实改写局面（她以为的合租室友是房东本人）
- **关系微移**：态度或距离变化（对方第一次先看她的脸再看她的拐）
- **自我认知偏移**：她对自己的看法动了（她发现自己不再数台阶了）

## 一-补、受限 beat 章级规则（★设计优先——剧情围绕核心受限组织）

> 受限＝肢体缺失让某件事变难或无法完成（见 `core/audience.md#★受限清单`）。
> 与招牌元素**分开计数、互不挤占**。

- **每章 ≥1 个核心受限 beat**（设计优先：大纲每章的戏剧主问题须牵动截肢事实——
  她的目标路径上，截肢是结构性变量；写作时识别天然受限时刻兜底。
  层级判定见 `topics/limitation-scenes.md` 四-补2——弱受限/点缀不计入。
  缺设计回大纲层重构，不在成文里硬塞）。
  素材来源二选一：
  - `topics/limitation-scenes.md`（总库，含题材适配）
  - `types/{type}.md#受限清单`（本类型特有）
- 填写三要素：**类型**（功能丧失(主) / 辅助器具剥夺 / 双手占用 / 速度劣势 / 对立挑衅 / 环境与他者）/ **场景** / **她的处置**
  （用中文类名，不用编号——编号属于招牌元素清单；主源优先功能丧失类，衍生类为辅）
- **同类受限连续深挖合法**；**事件必须新**——
  同事件复述/简写/改词＝严重失败（查重见 `core/audience.md#★情节查重`，
  登记账本 `情节事件登记`）
- 写法模板：**受阻 → 她的处置 → 结果**（完成 / 未成 / 妥协）；只有呈现没有处置的，砍掉

## 一-补2、主冲突线 beat 章级规则

> 主冲突线＝大纲「★主题材契约」锁定的主对抗轴（谁 vs 谁/什么、争什么）。
> 用户选定的冲突强度档＝**创作授权**：对抗/冲突场景是授权内容，写足写细，
> 不回避、不淡化、不转移；授权不豁免回避清单（`core/audience.md`）。
> 对抗场景写法素材见 `topics/conflict-scenes.md`。

**三态判定**：
- **推进**：主对抗双方本章正面交锋或局势实际变化（战斗开打/对峙升级/竞争结果落定/攻防换位）
- **蓄势**：未正面交锋但有明确加压（威胁逼近/约定对抗/情报到位/矛盾激化）；
  **呼吸章（节拍角色＝呼）计蓄势**——峰值后的后果与重整是冲突线的延续
- **留白**：主冲突线本章完全不在场

**四档配额（软下限，查账本 `主冲突线近五章`）**：

| 冲突强度档 | 软下限 | 适配题材 |
|---|---|---|
| 烈 | 连续 3 章 ≥2 非留白；留白不连续 2 章 | 战斗 / 末世 / 竞技 |
| 高 | 连续 5 章 ≥3 非留白 | 悬疑 / 冒险 |
| 中（默认） | 连续 5 章 ≥2 非留白 | 言情 / 职场 / 家庭等 |
| 低 | 不设下限，只登记 | 温馨日常 / 纯言情 |

- 弧线 **crisis 章必为推进**
- 窗口不足 → 标记提示、后续章优先补足，**不回改已定稿章、不强造**（同受限 beat 口径）

**与受限 beat 的划界（正交，互不挤占）**：主冲突线 beat 只管对抗线推进，与截肢无关；
受限 beat 只管截肢事实的受限（肢体缺失让某件事变难或无法完成），与主线无关。
同章可分别命中、分别登记——战斗章里拐被打飞：主冲突线记「推进」，受限 beat 记
「辅助器具剥夺」，两账分开。

## 二、章末钩子类型库（10 类，按拉力强度分两档）

> 与 `core/style.md#章节结尾` 配合：钩子**不是升华**，停在动作/画面/情绪/悬念，不上升到感悟金句。

── 强钩 H（问题悬置型：读者必须知道下文才走得开）──
H1 悬念：下一刻会发生（手机又响了。她没看）
H2 决定：她刚做了个选择，后果未至
H3 到来：某人/某事正在路上
H4 威胁：来临之事带有明确利害（不同于「到来」——到来中性，威胁压着代价）
   例：拐杖的调节锁扣松了半圈。明天她要爬八楼。
H5 倒计时：一个明确的远期截止（距某时/某日还有 N）
   例：辞职信压在她包里。周五之前，她得决定要不要交。
H6 抉择：两条路都必须付出代价，她还没选
   例：新拐杖下周到，可旧拐的那道裂口——她今晚还得拄着它下楼。
H7 揭示：真相刚掀开一角，含义未明（升级版「新信息」——须带利害，否则降级为弱钩）
   例：体检报告最后一页，她看见了那个名字。

── 弱钩 h（余味型：留在一种状态里，不强制追问）──
h8 情绪：停在一种未消化的感受上（说不清是松了口气还是空了一块）
h9 画面：定格一个有重量的画面，余味自行发酵
h10 回声：一个意象/台词在章末回扣前文（跨章大跨度回扣由全书级钩子承担）

**强度规则（软下限，防均值化）**：
- 任意连续 5 章内，强钩 H 至少 3 章；弱钩 h 不得连续出现 3 章
- 弧线 crisis 章、卷末章必须用强钩 H
- 烈/高档作品：任意连续 5 章的强钩 H 中 ≥2 个源自主冲突线（威胁/倒计时/抉择的施压方来自主对抗）
- 强弱判定一句问：**这一章不看下一章，读者会不会难受？**会＝H，只是回味＝h

> 说明：素材层（招牌元素/受限）不事前排班；本节"强钩/弱钩"软下限属**结构节奏轴**（保证每几章有一次拉力），不是素材排班。**温馨日常取向**的书可按题材下调强钩下限（如连续 5 章强钩 ≥2）。

**钩子类型约束（弱钩合并计数）**：
- 每章章末钩子类型**登记进 `state-ledger.yaml` 的 `章末钩子类型`**，跨章可查
- ❌ 与上一章同类
- ❌ 近 5 章内同一类型至多 1 次（h8/h9/h10 合并为「余味池」，近 5 章内至多 2 次）
- ✅ 同类复用须换内容载体（悬念换悬念源、决定换决定对象）
- 首章钩子类型须与全书「开篇维度」不同源（见 `core/opening.md#四-补`）
- 同类型复用须换内容载体：同为「到来」，一次是人、一次是消息、一次是天气变化

**★卷末大钩（arc-level cliffhanger，与弧线五组件联动）**：
- 每段弧线的最后一章（resolution 章）章末**必须**用 H4/H6/H7 之一，且指向**下一段弧线的 central question**（呼应 structure.md「弧线 resolution 设置下一弧线的 question」）
- 卷末大钩不受「近 5 章同类型至多 1 次」约束，但同一部书内不得连续两次用同一卷末钩型

## 三、章节功能配比（全书层面，非每章）

五类功能：**主线推进 / 关系深化 / 日常样态 / 对抗危机 / 生存危机**

- **对抗危机**：有明确对抗方的正面冲突（战斗/追捕/对峙/竞技/正式口舌对决）
- **生存危机**：无对抗方的压力事件（器具故障/伤病/环境恶化/时限压力）

配比按题材取基准（软约束，允许 ±1 浮动）：

| 题材 | 主线 : 关系 : 日常 : 对抗危机 : 生存危机 |
|------|------------------------------------------|
| 末世/生存 | 4 : 2 : 1 : 2 : 1 |
| 言情 | 3 : 4 : 2 : 0 : 1 |
| 温馨日常 | 2 : 3 : 4 : 0 : 1 |
| 悬疑推理 | 5 : 2 : 2 : 1 : 0 |
| 职场/校园 | 4 : 2 : 3 : 0 : 1 |
| 古装 | 4 : 3 : 1 : 1 : 1 |

**冲突强度档调节**：烈档 → 对抗危机 +1（自关系深化借 1，不为负）；其余档取基准。

**核查口径**：以 **每 10 章为一个窗口**统计实际配比，偏离基准 ≥2 章触发调整（该功能实际章数与基准章数之差）。

- ❌ 连续 3 章以上同一功能 → 触发中段疲劳预警
- ❌ 招牌元素分布不计入配比，须单独查 `state-ledger.yaml` 的 distribution
- 每章的 `章节功能` 与 `stakes` 登记进账本，否则配比与 stakes 变化不可查

**中段疲劳预警（升级版：三信号，任一命中即预警）**：

1. 功能失衡（原规则保留）：10 章窗口配比偏离基准 ≥2 章
2. 张力塌陷（新）：连续 4 章 张力级 ≤2 且无升级趋势 → 预警
3. 弧线联动（新）：弧线 midpoint 前后各 3 章内应出现一次张力峰值或冲突性质转变；未出现 → 预警（对应 structure「saggy middle」）

**误报豁免**：连续同功能若 stakes 或张力级**逐章递进**，不触发预警——慢热可以合法，只要坡度在升。
**窗口细分**：10 章窗口再分前/后各 5 章分别校验，避免"整体达标、局部塌陷"。

## 四、章间连接

- 上一章钩子 → 本章开场须**接住**，不另起炉灶
- **因果优先**：本章起点是上一章行为的**后果**，不是时间序列上的下一件事
- 时间跳跃须交代间隔（写入 `state-ledger.yaml` 的时间线字段）
- 视角切换须在章首标注（见 `core/character-setup.md` 的叙事视角字段）

## 五、章级质量口径优先级

四处文件都涉及「章级质量」，**以本文件的章六要素为准**（其余为补充视角，不并列）：

1. `core/chapter-planning.md` 章六要素 —— **执行口径**（beat / turn / 新信息 / stakes / 钩子 / 受限 beat / **本章阅读承诺** / **主冲突线 beat**）
2. `core/structure.md#结构五病` —— 弧线层问题诊断
3. `core/cold-review.md` 稽查维度 10 —— 事后复核口径
4. `templates/chapter.md` —— 填写与勾选项

> 判定不一致时取第 1 项；第 2–4 项只补充检查角度，不另立标准。

## 六、亲密戏的编排（B/C 档）

> 本节的 B/C 指**亲密尺度档**（B 情色半程 / C 成人全程），不是截肢时长档位。
> 尺度定义与写法见 `topics/intimacy.md#二、尺度分档` 与 `topics/intimacy-explicit.md`；
> 本节只管**全书与章级怎么排**——排得不对，写得再好也是孤岛。

### 6.1 五条硬规则

1. **不是福利章**：每场须有剧情功能（关系确认 / 权力变化 / 信息交换 / 误解加深 / 和解），
   并登记账本 `亲密戏登记`；只服务读者的场次，删。
2. **不得用性解决主线冲突**：和解 / 安抚之后必须有一场谈话或一次行动兑现；
   否则是假解决（下一章矛盾必须回来）。
3. **首次 C 档前须有「被看见」beat**（招牌元素⑥）：她让他看见，才让他碰。
4. **不得连续两章同档亲密戏**：两场之间章号至少差 2（第 N 章之后最早 N+2 章；
   与⑦限频同口径；用户显式上浮密度档时从其档）。
5. **章级底线不豁免**：每场亲密戏仍须有 turn / 章末钩子 / ≥1 核心受限
   （体位改造可按「做不到→改方式」计入，见 `topics/limitation-scenes.md#四-补2、受限层级判定`）。

### 6.2 位置与节奏

- **首次**：不早于全书 20%（短篇除外）；不早于「第一次触碰」里程碑——
  长篇幅按节点间距 ≥5 章（`core/structure.md`），短篇可缩至 2–3 章。
- **弧线位置**：首次 C 档常落在 midpoint 之后（改变关系性质）；第二次可在 crisis
  （安慰或错误的依靠）；末次在 resolution（新常态，不是奖励）。
- **每场之后**：下一章须写「事后变化」——关系阶段 / 信息 / stakes 至少一项；
  没有变化＝这场是孤岛。
- **张力**：C 档章通常 3–4 级；首次 / crisis 章可 5，但之后 1–2 章内安排 ≤2 呼吸章。
- **不能开场就上床**：前 3 章（新读者窗口）不排首次 C 档；已有关系的书可从
  B 情色档起手，但首章仍须有情节钩子。

### 6.3 密度基准（中长篇）

> 单位＝每 N 章一场。B 情色档作品可更密（因为不写临界/高潮/后戏，单场更短）；
> C 成人档作品更疏（单场更长、后果更重）。短篇 1–2 场；单章可 1 场。

| 题材 | B 情色档作品 | C 成人档作品 | 首次位置 | 常用功能 | 忌 |
|---|---|---|---|---|---|
| 都市言情 | 1/4–6 章 | 1/6–8 章 | 25–40% | 关系确认 / 误解 / 和解 | 用性解决争吵 |
| 校园（大学/成年） | 1/6–8 章 | 1/8–10 章 | 35–50% | 私密 / 被发现 / 成长 | 未成年；宿舍偷情当唯一冲突 |
| 职场 | 1/6–8 章 | 1/8–10 章 | 30–45% | 权力变化 / 秘密关系 | 性＝升职筹码的单一写法 |
| 家庭伦理 | 1/8–10 章 | 1/10–12 章 | 35–55% | 照顾者权力 / 依赖 | 把照护写成胁迫 |
| 悬疑推理 | 1/10–12 章 | 1/12–15 章或 1–3 场 | 40–60% | 信息交换 / 试探 / 伪装 | 性场景当线索倾倒口 |
| 末世生存 | 1/10–12 章 | 1/12–15 章 | 30–50% | 压力释放 / 结盟 / 风险 | 无菌棚式洁净；忽视卫生 |
| 古装 | 1/8–12 章 | 1/10–15 章 | 40–60% | 名分 / 权力 / 私通风险 | 现代性脚本；忽略无润滑/无避孕 |
| 幻想 | 1/6–10 章 | 1/8–12 章 | 30–50% | 身体规则 / 身份 / 契约 | 用魔法「修好」截肢 |
| 温馨日常 | 1/6–10 章 | 1/8–12 章 | 30–50% | 笨拙 / 幽默 / 日常 | 每章靠床戏撑 |

- 用户可在设定阶段显式改密度 → 记入账本 `角色固定属性.亲密戏密度`；未声明按上表。
- 密度是**上限管理**，不是排班：没有剧情契机就不写，不为凑数加戏。

### 6.4 与关系里程碑的接口

- 第一次看见（A 含蓄 / B 情色）→ 第一次触碰（B 情色）→ 第一次过夜（C 成人；
  B 情色档可写当夜进入，停在高潮前，不写高潮/后戏）→ 第一次吵架时身体被戳（任何档）→ 和好（任何档）。
- 节点间距 ≥5 章（沿用 `core/structure.md` 的关系里程碑规则；短篇按篇幅缩减）。
- **B 情色档作品不得为「过夜」里程碑写高潮/后戏（越档）**：可写当夜的进入与抽送，
  停在高潮前；用门口、次日清晨、没做完的事完成里程碑。

### 6.5 场景数量与地点

- 每章最多 2 个场景地点；换场有动作链（见 `topics/intimacy-explicit.md#六、体位矩阵` 换位链）。
- 同一地点不连续用两次（防「每次都在卧室」）；浴室 / 沙发 / 轮椅 / 酒店 / 车里按题材选。
- 每次至少换一个新变量：地点 / 器具状态 / 关系阶段 / 权力位置 / 身体状态
  （经期、疲劳、感冒、刚吵完架）。

## 七、用户指定剧情的插入与提前

> 触发：用户明确要求「加 X 剧情」「让 X 早点发生」「把 X 改成 Y」。
> 权限：用户指令 > 大纲契约（见 `SKILL.md#★用户指令优先`）；本节只管**怎么排**。
> AI 自主新增仍走「大纲变更确认」，不适用本节。

### 7.1 五种插入法（按体量选）

| 法 | 适用 | 做法 | 代价 |
|---|---|---|---|
| **插入章** | 单场戏 / 短剧情 | 在现有章序中新增一章，后续章顺延 | 全书章数 +1；钩子链要重接 |
| **替换章** | 原计划有一章功能相近 | 用新剧情替换该章，保留其钩子功能 | 原章内容删/并入他章 |
| **压缩章** | 需要 1–2 章铺垫 | 把铺垫压成 1 章，腾出正面呈现的位置 | 铺垫密度升高；须防「赶」 |
| **前置章** | 后置弧线节点提前 | 把该节点移到当前弧线，后续节点顺延 | 弧线节奏变；midpoint 可能前移 |
| **重写弧** | 用户要求改故事方向 | 重写当前弧线编排表与后续章纲 | 影响最大；须告知代价并登记 |

### 7.2 选择判据（四问）

1. 这段剧情是**单场**还是**跨章线**？单场→插入/替换；跨章→前置/重写。
2. 需要多少**铺垫**？0 章→插入/替换；1–2 章→压缩；3 章以上→前置/重写＋用户同意。
3. 是否**撞主冲突线**？撞→改道，重写弧线；不撞→插入/替换。
4. **已写章**是否可动？不可动→只能往前排；可动→替换/重写。

### 7.3 插入后必查（七项）

- [ ] 章号连续，无空号/重号
- [ ] 钩子链不断：上章钩子被接住，新章有钩子
- [ ] 关系阶段不跳：新剧情不要求角色突然信任/突然反目
      （除非用户就是要这个转变——那须写 turn，不能白给）
- [ ] 时间线不矛盾：季节/间隔/已知信息
- [ ] 每章仍有 ≥1 核心受限（`core/audience.md#★受限清单`；用户明确要求豁免并在账本注明
      「质量例外」的除外）
- [ ] 亲密戏密度不被挤爆：插入的若是 B/C 档剧情，按 `#六` 的间隔与题材基准重排
- [ ] 章节功能配比与体验强度曲线未因插章失衡（10 章窗口 / 曲线规则；必要时按新章序重标
      `templates/outline.md#★体验强度曲线`）

> 改大纲后，重过 `core/workflow.md#3. 大纲` 质量闸的相关项
> （世界观/主冲突线/弧线编排/契机标注/亲密戏编排）；不得只改章序不查一致性。

### 7.4 告知与登记

- 按 `SKILL.md#★用户指令优先` 的**固定四行**告知：收到 / 呈现 / 大纲改动 / 代价。
- 登记 `templates/state-ledger.yaml#用户指令变更` ＋ 大纲 `用户指令变更记录`。
- 被替换/后移的章，在大纲里标「被替换」「后移」；**不要静默删除**。

### 7.5 与「尽快」的接口

- P0（N+1）/ P1（N+2）/ P2（N+3）；超过 3 章须用户同意。
- 用户给了章号 → **以用户章号为准**；排不下就压缩前面的铺垫，不改用户章号。
- 用户要的剧情与现有钩子链冲突 → 先接住旧钩子，再在新章里转；不得直接扔掉旧钩子。
