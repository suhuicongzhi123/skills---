# 每章剧情安排

> 类型无关。大纲阶段排布、每章开写前核对。
> 分工：`core/structure.md` 管弧线层级，`core/scene.md` 管场景内部，**本文件管章与章之间**。

## 一、章五要素（每章开写前必须填）

| 要素 | 内容 | 判据 |
|------|------|------|
| **本章 beat** | 推进所在弧线的哪一步 | 填不出 → 这章没有存在理由 |
| **本章 turn** | 章内哪个瞬间改变了什么 | 无 turn → 流水账 |
| **新信息** | 读者这章新知道了什么 | 全无新信息 → 砍或合并 |
| **stakes 变化** | 相对上一章升了，还是换了类 | 连续 3 章无变化 → 节奏 plateau |
| **章末钩子** | 停在什么上（见下） | 无钩子 → 断更风险 |
| **受限 beat** | 本章哪个受限场景（见下） | 无受限 → 这章缺了日常底色 |

## 一-补、受限 beat 章级规则（★每章必备）

> 受限＝肢体缺失让某件事变难或无法完成（见 `core/audience.md#★受限清单`）。
> 与招牌元素**分开计数、互不挤占**：招牌元素管上限，受限管下限。

- **每章 ≥1 个受限 beat**，开写前先选好，来源二选一：
  - `topics/limitation-scenes.md`（总库，含题材适配）
  - `types/{type}.md#受限清单`（本类型特有）
- 填写三要素：**类型**（能力丧失 / 器具剥夺 / 双手占用 / 速度劣势 / 对立挑衅）/ **场景** / **她的处置**
  （用中文类名，不用编号——编号属于招牌元素清单）
- **不连续两章用同一类**（查账本 `受限类型近三章`）
- 写法模板：**受阻 → 她的处置 → 结果**（完成 / 未成 / 妥协）；只有呈现没处置的，砍掉

## 二、章末钩子类型库（轮转使用，❌ 不连续同类）

- **悬念**：下一刻会发生（手机又响了。她没看）
- **新信息**：刚得知/刚发现，含义未明
- **情绪**：停在一种未消化的感受上（说不清是松了口气还是空了一块）
- **决定**：她刚做了个选择，后果未至
- **到来**：某人/某事正在路上
- **画面**：定格一个有重量的画面，余味自行发酵

> 与 `core/style.md#章节结尾` 配合：钩子**不是升华**，停在动作/画面/情绪/悬念，不上升到感悟金句。

**轮转硬约束**（防章末套路化）：

- 每章章末钩子类型**登记进 `state-ledger.yaml` 的 `章末钩子类型`**，跨章可查
- ❌ 与上一章同类；❌ 与近 5 章内已用类型重复超过一次的
- 首章钩子类型须与全书「开篇维度」不同源（见 `core/opening.md#四-补`）
- 同类型复用须换内容载体：同为「到来」，一次是人、一次是消息、一次是天气变化

## 三、章节功能配比（全书层面，非每章）

四类功能：**主线推进 / 关系深化 / 日常样态 / 危机（含器具故障）**

配比按题材取基准（软约束，允许 ±1 浮动）：

| 题材 | 主线 : 关系 : 日常 : 危机 |
|------|--------------------------|
| 末世/生存 | 4 : 2 : 2 : 2 |
| 言情 | 3 : 4 : 2 : 1 |
| 温馨日常 | 2 : 3 : 4 : 1 |
| 悬疑推理 | 5 : 2 : 2 : 1 |
| 职场/校园 | 4 : 2 : 3 : 1 |
| 古装 | 4 : 3 : 2 : 1 |

**核查口径**：以 **每 10 章为一个窗口**统计实际配比，偏离基准 2 格以上触发调整。

- ❌ 连续 3 章以上同一功能 → 触发中段疲劳预警
- ❌ 招牌元素分布不计入配比，须单独查 `state-ledger.yaml` 的 distribution
- 每章的 `章节功能` 与 `stakes` 登记进账本，否则配比与 stakes 变化不可查

## 四、章间连接

- 上一章钩子 → 本章开场须**接住**，不另起炉灶
- **因果优先**：本章起点是上一章行为的**后果**，不是时间序列上的下一件事
- 时间跳跃须交代间隔（写入 `state-ledger.yaml` 的时间线字段）
- 视角切换须在章首标注（见 `core/character-setup.md` 的叙事视角字段）

## 五、章级质量口径优先级

四处文件都涉及「章级质量」，**以本文件的章五要素为准**（其余为补充视角，不并列）：

1. `core/chapter-planning.md` 章五要素 —— **执行口径**（beat / turn / 新信息 / stakes / 钩子）
2. `core/structure.md#结构五病` —— 弧线层问题诊断
3. `core/cold-review.md` 稽查维度 10 —— 事后复核口径
4. `templates/chapter.md` —— 填写与勾选项

> 判定不一致时取第 1 项；第 2–4 项只补充检查角度，不另立标准。
