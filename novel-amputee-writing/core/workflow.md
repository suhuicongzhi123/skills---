# 创作工作流

> 类型无关。每阶段按需注入对应专项（见 SKILL.md 注入索引）。

## 阶段总览

构思 → 大纲 → 人物设定 → 章节写作 → 润色

## 1. 构思
- 确定题材（现实向/幻想向）、基调、核心冲突
- 确定主角截肢类型与基本处境
- **询问用户是否开启独立子代理冷读稽查流程**（见 `core/cold-review.md`）：据此设定全书稽查开关，开启则每章写完经独立子代理冷读纠错，不开启则仅单代理自审
- 注入：`core/audience.md`、`genre/{题材}.md`

## 2. 大纲
- 搭故事骨架：起承转合、章节划分、关键场景
- 弧线与结构规划（`core/structure.md`：四层级/四法则/弧线五组件）
- **开篇切入方式选择**（`core/opening.md`：从维度库选一个维度并标注，禁止默认走 routine）
- 标注哪些场景涉及拐杖/假肢/日常动作/身体细节/亲密/W视角
- **大纲质量闸（进章节写作前须过）**：
  - [ ] 世界观已建立并锁定（无障碍水平/社会态度/器具可得性，见 `core/worldbuilding.md`）
  - [ ] central question 已定义，且**非默认"她能否接受自己"**（除非题材确为身份认同，见 `core/structure.md`）
  - [ ] 弧线编排表已填：每段弧线有 question / midpoint shift / crisis / resolution
  - [ ] 每段弧线改变故事**永久状态**，无 filler arc
  - [ ] 招牌元素已**全书分配**（每 2–3 章 1 个、不连续重复、清单内轮转）
  - [ ] 时间线已排（跨度/间隔/季节无矛盾）
  - [ ] 每章五要素可填（beat / turn / 新信息 / stakes 变化 / 钩子，见 `core/chapter-planning.md`）
- 产出：`templates/outline.md`

## 3. 人物设定
- 收集角色设定（`core/character-setup.md`）
- 注入：`types/{type}.md` 建立主角生理事实基线
- 产出：`templates/character-card.md`

## 4. 章节写作
- **逐章创作，禁止一次生成整篇**：每章流程为 写当前章 → 章末核查 →（可选冷读稽查）→ 更新 `state-ledger.yaml` → 等用户确认进入下一章。不批量产出多章，不一次性写完整本。
- 逐章写，按场景按需注入专项（拐杖/假肢/日常/身体/亲密/W）
- 场景构建（`core/scene.md`：场景四问/入口/对话双功能/必要性测试）
- 每个涉及截肢细节的场景，先读对应专项再写
- 产出：`templates/chapter.md`

## 5. 润色
- 检查回避清单（幻肢痛/劳损/伤口/苦难渲染/猎奇/励志二元）
- 检查代入感与日常真实
- 节奏诊断（`core/pacing.md`：节奏四病/句子节奏匹配场景速度）
- 去AI化润色（`core/style.md#去AI化润色`）
- 章节结尾把控（`core/style.md#章节结尾`）
- 风格统一（`core/style.md`）

## 6. 状态核查流水账
- 开书前：初始化 `templates/state-ledger.yaml`，固定属性从 character-setup 锁定
- 每章开写前：读账本，确认侧别/部位/拐杖状态
- 每场景写完：更新账本（拐杖位置、姿态、物品位置、open_setups、distribution）
- 章末核查：侧别一致 ✓ / 部位一致 ✓ / 生理事实 ✓ / 拐杖连续 ✓ / 物品位置 ✓ / 双手占用 ✓
- 全书完成：抽查关键节点

## 7. 冷读稽查（由创作前用户选择决定）
- 每章写完 → 独立子代理冷读稽查 → 修正 → 下一章
- 详见 `core/cold-review.md`
- 是否启用由构思阶段询问用户决定（见上文"1. 构思"）
- 子代理不可用 → 单代理自审，明确告知用户质量下降

## 注入原则
- 不主动全量加载专项，写到哪读到哪
- 类型差异小节用 `types/{type}.md#X` 叠加
