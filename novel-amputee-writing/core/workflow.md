# 创作工作流

> 类型无关。每阶段按需注入对应专项（见 SKILL.md 注入索引）。

## 〇、工作流模式（flash / pro / max）

> 模式在人物设定阶段收集流程**第 13 题（末题）选定**，开书后全书锁定（中途切换须告知用户
> 账本衔接方案）。三模式共享：大纲质量闸、章六要素、严重错误五项合一闸、章末核查清单
> ——模式只改变「写作与审查的分工方式」，不豁免任何质量闸。

| 模式 | 定位 | 分工 | 适用 |
|---|---|---|---|
| **flash** | 自写自审 | 单代理：写作＋章末自查（含五项合一闸） | 快速成稿/短篇/试笔 |
| **pro** | 一写一审 | 主代理写作＋自查 → **独立冷读子代理**逐章稽查 → 主代理修正＋记账 | 中长篇默认推荐 |
| **max** | 队长＋队员 | **队长**（主代理）：剧情安排与整体把控，不写正文；**写作员**：成文；**审查员**：冷读稽查；**记账员**：账本更新 | 长篇/多线复杂/最高质量要求 |

**各模式章循环**：

> **交付前最后一步（三模式统一）——自问：脚本跑了吗？**
> 有 gatecheck 的 PASS 输出 → 才可交付；没有 → **立即运行**，不得交付。
> 这一问是硬性显性步骤，不是提醒——跳过它直接交付＝严重制度失败（SKILL 〇-补 第 6 类）。

- **flash**：写当前章 → 章末自查（五条铁则执行）→ 更新账本 → **运行 gatecheck（自问：脚本跑了吗？）→ PASS** → 携机检披露交付 → 等用户确认 → 下一章
- **pro**：写当前章 → 章末自查 → 冷读稽查（`core/cold-review.md` 22 维度）→ 据报告修正 → 更新账本 → **运行 gatecheck（自问：脚本跑了吗？）→ PASS** → 携机检披露交付 → 等用户确认 → 下一章
- **max**（队长视角）：排章派单 → 收草稿 → 快检 → 审查员稽查 → 裁定修正（小错自改，大错回炉写作员）→ 定稿 → 记账员落账 → 队长终审 → **运行 gatecheck（自问：脚本跑了吗？）→ PASS** → 携机检披露交付 → 等用户确认 → 下一章

**max 模式职责细则**（各角色上岗声明＝该角色的行为契约，随任务包传递）：

- **队长（主代理）**：大纲与弧线把控、每章任务包编制（章六要素＋场景要求＋核心受限设计＋
  注入文件清单）、基调与主冲突线配额监控、审查报告裁定、账本终审——**不亲自写正文**。
  上岗自认：我是工坊主理人，对整本书负责——订单（大纲契约）在我手里，
  走货路线（基调循环）不换道，交出去的每章都有完整手续
- **写作员（子代理）**：领任务包成文；交草稿前完成章末自查（五条铁则留痕随草稿一并提交）；
  不自改账本、不自行扩章。上岗自认：我是领活的写手——生理事实零错是本分，
  受限戏是主菜，任务包之外的需求交回队长，不自作主张
- **审查员（子代理）**：按 `core/cold-review.md` 全维度稽查草稿（独立上下文），
  只出报告不改文
- **记账员（子代理）**：按**定稿章**更新账本（本章登记/情节事件登记/distribution/
  核查记录）——max 模式下**唯一写账者**，防双账本。上岗自认：我是唯一写账的
  账房，原则是账实相符——没发生的流程不登记，登记的数字必须与产物对得上
- 交接一律**文件化中转**（章任务包 / 章草稿 / 审查报告均落盘于小说项目工作区），
  禁止超长上下文内联传递
- **章任务包的承载**：用 `templates/chapter.md` 章节信息区（队长填齐章六要素＋核心受限
   设计＋注入文件清单后交付写作员；写作员在该文件上续写正文）——不另设任务包模板
- **选定模式全书锁定，禁止降级**：子代理调用临时失败 → 重新调用直至成功，
  不得改跑更低模式交付——违规章按选定模式重跑完整流程

**单上下文分角色扮演 ≠ 子代理调用**：同一上下文里切换「现在我是审查员」继续
干活，没有全新上下文与宿主任务实例，**本质是自审伪装成多人**——判假执行
（`SKILL.md#〇-补` 假执行判定第 3 形态）

## 〇-补、执行完整性硬卡口

> **口头声明 ≠ 执行**：宣称某模式≠实际执行该模式。执行以**证据链**为准
> （账本 `工作流执行日志` ＋ 产物文件）；无证据＝未执行。三卡口＋交付闸如下，
> 每章交付用户前必过（三种模式同适用，卡口②③按模式有「不适用」态）。

**卡口① 自查全覆盖**：章末自查报告须**逐一列出** `templates/chapter.md` 核查清单
**全部条目**（剧情结构/受限与不便/严重错误五项合一闸/一致性/成文质量关/文学自评），
每项留痕三件套（项名｜判定｜证据），报告末尾报**「X/X 全查」总计数**——
缺任一项＝该项未查，卡口不通过（五条铁则之⑤）。

**卡口② 稽查全覆盖**（pro/max 适用，flash＝不适用）：冷读报告须含
`core/cold-review.md` **全部 22 个维度的逐项判定**（维度号｜判定｜结论）。
受理前先验覆盖数：**22/22 才可受理**；缺维度 → 退回子代理补查，
**不得据不全报告修正与交付**。

**卡口③ 模式执行保真**：实际调用与产物须匹配选定模式的必需集——

| 模式 | 必需代理 | 必需产物（落盘文件） |
|---|---|---|
| flash | 本体 | 章草稿＋自查报告 |
| pro | 本体＋冷读子代理 | 章草稿＋自查报告＋审查报告 |
| max | 队长＋写作员＋审查员＋记账员（**各自独立**，不得合并扮演） | 大纲（首章前置）＋章任务包＋章草稿＋审查报告＋自查报告＋记账摘要（记账员） |

- **调用凭证化**：pro/max 模式下 `调用代理` 逐角色登记**宿主调用凭证**
  （任务/会话标识，如 `ses_xxx`/`task_id`）；无凭证的「名字列表」＝未经验证的
  声明＝机检 FAIL
- **子代理产物指纹**：每个产物文件末行带 `生成指纹: <该产物签发角色的凭证>`——
  指纹与账本对应角色凭证同号（角色↔产物映射：max 章任务包→队长、章草稿/自查
  报告→写作员、审查报告→审查员；pro 章草稿/自查报告→本体、审查报告→冷读）；
  **同一章内各角色凭证两两互异**（同凭证签发多角色产物＝合并扮演实锤）；
  指纹不同号/缺指纹行＝机检 FAIL
- **假执行判定**（三种形态，命中任一 → 该章**不得交付**，按选定模式重跑完整
  流程，不得降级交付）：
  1. 宣称 max 实跑 pro/flash（无写作员/记账员调用记录或无对应产物）
  2. 宣称 pro 实跑自审（无冷读报告）
  3. **单上下文分角色扮演冒充多人**（无宿主任务实例的自称「审查员/写作员」）
     ——写作/自查/冷读同主体完成却登记多人；同凭证签发多角色产物同判
- 逐章登记进账本 `工作流执行日志`（选定模式/实际执行模式/调用代理＋凭证/产物/
  三卡口判定）

**PASS 印章**：gatecheck 每次 PASS 自动为各章生成
`gate-pass-第N章.txt`（**交付凭证**：正文SHA＝sha256(章草稿)[:16]＋正文字数
＋印章＝sha256(章号+章草稿+自查报告+审查报告)[:16]，**脚本生成，手写无效**；
FAIL 运行不生成凭证）；任何产物事后篡改或手写伪造 → 下次机检重算比对 FAIL →
该章须重跑完整流程重新过闸。「下章开写前必重验上章凭证」为固定环节
（每章循环首步），伪造历史在任何后续真跑中被揭穿。

**交付正文绑定（正文与脚本深度绑定）**：向用户交付的正文**必须逐字节来自
被机检的章草稿文件**——章草稿为三模式必需产物，无草稿＝无交付物＝机检 FAIL；
交付正文时**随正文附 gate-pass 凭证内的「正文SHA」与「正文字数」**（贴出即可，
不要求用户做任何判断——但正文若与被检文件不一致，SHA 立即可见地不符）；
交付后被换正文 → 下章开写前重验时 SHA/印章不符 → FAIL → 该章重跑完整流程。

**交付闸（合并判定）**：卡口①②③全过（含「不适用」态）→ 方可向用户交付本章；
任一未过 → **不得交付**，补执行缺项后重过闸。「等用户确认进入下一章」的例外①
以交付闸通过为前提——未过闸的章不存在「等确认」，只存在「补执行」。

**脚本运行显性条件＋披露义务（针对脚本漏跑——严重制度失败的处置）**：

- **脚本运行＝交付的显性前置条件**：gatecheck 实际运行并输出 PASS 是
  「交付闸: 通过」的唯一合法来源——账本登记「通过」但无脚本运行记录＝
  该登记无效，交付无效
- **对话中披露（每章交付必附）**：向用户交付正文时，交付信息末尾**必须**
  附机检披露行——`机检：PASS（第N章，gatecheck 全项通过）`；无此行的交付
  ＝脚本漏跑嫌疑交付，用户可直接拒收
- **漏跑即严重制度失败**：跳过 gatecheck 直接交付（或事后发现未跑）＝
  **严重制度失败**（`SKILL.md#〇-补` 第 6 类）——须在对话中**如实披露**
  「脚本漏跑——本交付无效」，立即补跑脚本，FAIL 则修复后重跑，重新交付；
  隐瞒漏跑不报＝制度失败＋诚信违规双重叠加
- **自问机制（防惯性遗忘）**：每章交付动作发出前的最后一问固定为
  **「脚本跑了吗？」**——自问无 PASS 证据 → 停止交付、先跑脚本；
  该自问写进章循环与章末核查清单，是显性步骤不是心理暗示
- **执行日志登记**：`工作流执行日志` 增 `机检运行` 字段（是｜否＋输出结论）——
  「是」须对应本次会话实际执行的脚本运行；填「是」但拿不出 PASS 输出＝
  又一层假登记；机检校验该字段须为「是」

**机检条款（能跑 python 的环境强制）**：交付闸以脚本输出为准——
`python scripts/gatecheck.py <小说项目目录>`（可加 `--chapter N` 指定关注章——
**不豁免其余章检查**，历史章 FAIL 一并报整体 FAIL，防展示性通过），
**输出 PASS 才算过闸**。机检项＝结构与覆盖（日志完整性/章号连续/模式保真
——选定≠实际一律 FAIL，不得降级/代理凭证化＋凭证互异/产物三验＋生成指纹/
维度覆盖 22/22/输入隔离/自查交叉/闸判定）＋独立性内容信号：冷读引文实证
（命中草稿原文引文 ≥3 条——未读草稿的空报告 FAIL）/主语污染（报告含
「我写/作为队长」类主上下文人称模式＝非独立 FAIL）/同源判定（审查与自查
22 维判定向量全同＝同源伪装 FAIL）/PASS 印章（sha256 重算比对，篡改或
手写伪造＝FAIL 须重跑）。
**无 python 环境＝无法过闸＝不得交付**（交付闸字段唯一合法值「通过」，
不存在无 python 的降验形态）。机器可验格式：自查覆盖/稽查全覆盖 `X/X`、
审查报告逐行「维度N｜判定｜结论」、各产物末行 `生成指纹: <角色凭证>`、
自查报告落盘为文件（三模式必填，末行 `自查覆盖: X/X 全查`）
（格式规范见 `templates/chapter.md` 铁则⑤与 `core/cold-review.md` 三节）。

## 阶段总览

构思 → 人物设定 → 大纲 → 章节写作 → 润色

## 1. 构思
- 确定题材（现实向/幻想向）、基调、核心冲突
- 确定主角截肢类型与基本处境
- 注入：`core/audience.md`、`genre/{题材}.md`

## 2. 人物设定
- **按逐题提问协议收集角色设定**（`core/character-setup.md` 收集流程：
  一次一题、交互窗口带选项弹出、选项+效果、答后思考再问下一题；
  跳过仅限用户主动提出且须弹默认值确认包由用户确认）
- 注入：`types/{type}.md` 建立主角生理事实基线
- **收集流程末题（第 13 题）选定工作流模式**（flash 自写自审｜pro 一写一审｜
  max 队长＋队员，见 `core/workflow.md#〇、工作流模式`）：据此设定全书写作与
  审查分工——此询问的**唯一入口**，收集流程被跳过时默认 pro（最弱档不作兜底出口——flash 须显式选定）
- 产出：`templates/character-card.md`

## 3. 大纲
- 搭故事骨架：起承转合、章节划分、关键场景
- 弧线与结构规划（`core/structure.md`：四层级/四法则/弧线五组件）
- **开篇切入方式选择**（`core/opening.md`：从维度库选一个维度并标注，禁止默认走 routine）
- 标注哪些场景涉及拐杖/假肢/日常动作/身体细节/亲密/W视角
- **大纲质量闸（进章节写作前须过）**：
  - [ ] 世界观已建立并锁定（无障碍水平/社会态度/器具可得性/**缺失解释框架**，见 `core/worldbuilding.md`）
  - [ ] central question 已定义，且**非默认"她能否接受自己"**（除非题材确为身份认同，见 `core/structure.md`）
  - [ ] **开篇维度已选并标注**（从 `core/opening.md` 维度库主动选择，填入
    `templates/outline.md` 开篇节；「已用开篇维度」已核对避开——见 opening.md 多样性硬约束）
  - [ ] 弧线编排表已填：每段弧线有 question / midpoint shift / crisis / resolution
  - [ ] 每段弧线改变故事**永久状态**，无 filler arc
  - [ ] 招牌元素**剧情契机已标注**（识别各章天然素材契机，不排班分配——
    见 `core/audience.md` 两档供给与 `templates/outline.md` 剧情契机标注）；
    限频预检通过（常规型同一元素间隔 ≥2 章；8 章健康度预检＝数契机标注表「对应元素」列
    在任意连续 8 章内的去重类数 ≥4，不足提示检查契机标注遗漏）。
    **预检不过时：在契机标注表备注「该章不取用」即可（契机是必要条件非充分条件），
    不回改剧情**
  - [ ] 时间线已排（跨度/间隔/季节无矛盾）
  - [ ] 每章六要素可填（beat / turn / 新信息 / stakes 变化 / 钩子 / 受限 beat + **本章阅读承诺** + **主冲突线 beat**，见 `core/chapter-planning.md`）
  - [ ] **主题材契约已填**（冲突强度档 / 主冲突线 / 基调与基调核心循环 / 创作授权声明，见 `templates/outline.md#★主题材契约`）；
    弧线编排表每段弧线已标注「主冲突线推进」列；弧线命名与走向均在基调循环内（无内幕转向/存在论升级/道德困境化）
  - [ ] **每章剧情围绕核心受限设计**（各章戏剧主问题牵动截肢事实——每章 ≥1 核心受限的
    设计层保证，见 `core/chapter-planning.md#一-补`）
  - [ ] 题材为幻想向/科幻/赛博朋克时：`题材特有设定` 已写明豁免的 physi 条目
    （见 `core/physio-audit.md#题材豁免`），未写明即不豁免
  - [ ] 古装向题材：器具表已在世界观里自建（见 `genre/historical.md`）
  - [ ] **体验强度曲线已排**（张力级 1–5 与节拍角色，见 templates/outline.md#★体验强度曲线）
  - [ ] **前 3 章拉力坡度已标**（张力级，见 core/opening.md#四-补2）
  - [ ] **亲密戏编排表已填**（B 情色档 / C 成人档；密度按题材基准，首次位置/间隔/事后变化——
    见 `core/chapter-planning.md#六、亲密戏的编排（B/C 档）`；无亲密戏则填「无」）
  - [ ] **用户指定剧情已排入**（若有：按 `SKILL.md#★用户指令优先` 给出章号、登记
    `用户指令变更`；无则填「无」）
- 产出：`templates/outline.md`

## 4. 章节写作
- **逐章硬性要求：禁止一次生成整篇**——不批量产出多章，不一次性写完整本
- 每章循环按所选模式执行（见 `core/workflow.md#〇、工作流模式`：
  flash 自写自审 / pro 写后冷读 / max 队长派单——写作员成文时同样受本节全部约束）
- 逐章写，按场景按需注入专项（拐杖/假肢/日常/身体/亲密/W）
- **写亲密戏前**：读 `topics/intimacy.md` 定档位与边界；B 情色档 / C 成人档再读 `topics/intimacy-explicit.md`
  （B 情色档读 §〇–§七＋§十–§十六，跳过 §八/§九）；先确认账本 `亲密尺度档` 与人物卡 `残端接触边界`，

  `SKILL.md#★用户指令优先`——直接改大纲、给章号、告知影响、登记 `用户指令变更`，

  第 4 类（`SKILL.md#〇-补`，整章回炉）。确认通过的新元素登记进账本 `大纲对齐`
- **大纲节点消费自查**（仅约束 AI 自主提前）：大纲后置章的爆点素材（危机爆发/最大受限/关键转折/卷末大钩）

## 6. 状态核查流水账
- 开书前：初始化 `templates/state-ledger.yaml`，固定属性从 character-setup 锁定

- 每章开写前：读账本，确认侧别/部位/拐杖状态
  - **读全本不读滚动段**：核查记录只读近 5 章，历史部分不进上下文（见下）
- 每场景写完：更新账本（场景序号、拐杖位置、姿态、物品位置、open_setups、distribution）
- 章末登记 `本章登记` 块（beat / turn / 新信息 / 章节功能 / stakes / 章末钩子类型 / **受限beat** / **主冲突线beat** + **阅读承诺 / 张力级 / 节拍角色 / 上章钩子接住 / 上章钩子回收**）＋ `情节事件登记`（本章新事件，查重数据源）
- 章末更新 `用户指令变更` 状态（执行中 / 已完成 / 已被取代）——用户指令的剧情在本章呈现后
  标「已完成」；若用户改口，标「已被取代」并新增一条（不删旧记录）
- 章末登记 `工作流执行日志`（选定模式/实际执行模式/调用代理/产物/稽查全覆盖/交付闸——
  证据链登记，见 `#〇-补、执行完整性硬卡口`；未过交付闸的章不得进入「等用户确认」）
- 章末核查：侧别一致 ✓ / 部位一致 ✓ / 生理事实 ✓（**含未覆盖动作按生理事实推断**，见 `core/physio-audit.md#未覆盖动作兜底`）/ **移动-辅具一致 ✓（拐杖分离检测，见 `topics/crutch-usage.md` 四-补）** / 物品位置 ✓ / 双手占用 ✓ /
  beat 与 turn ✓ / **主冲突线窗口 ✓（冲突强度档配额，见 `core/chapter-planning.md#一-补2`）** / **基调符合 ✓（本章在基调核心循环内，见 `templates/outline.md#★主题材契约`）** / **情节查重 ✓（比对账本 `情节事件登记` 近 5 章）** / stakes 变化 ✓ / 钩子类型 ✓ / 密度与频率 ✓ /
  **受限每章 ≥1 核心受限 ✓（设计优先；同域深挖合法，事件必须新——见 `core/chapter-planning.md#一-补`）**
- 章末核查执行规范：按 `templates/chapter.md#章末核查清单（必过 + 文学自评）` 五条铁则执行
  （留痕三件套 / ★深查项附过程 / 计数项报数 / 零发现反证轮）——**无证据的 ✓ 无效**；
  冷读命中而本章自查曾判 ✓ 的维度记「自查失察」（同一维度连续 2 章失察 → 下章该维度逐字重查，
  见 `core/cold-review.md` 五-补）
- **滚动窗口**：`核查记录` 只保留近 5 章，更早的移入同目录 `state-ledger-archive.yaml`，

  开书时随账本一并创建于小说项目工作区，技能包内无此文件
- 全书完成：抽查关键节点
