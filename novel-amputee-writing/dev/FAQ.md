## 一、机检与验证

### Q1: 为什么机检PASS了，冷读还是发现问题？

**A**: 机检只验证**格式与枚举合法性**，不验证**语义正确性**。

**例子**：
- **[18] 验证**"受限beat层级"是否填了合法枚举值（核心/在场/余波/弱受限），**但不验证**分层判定是否正确
  - 填了"核心"但实际只是"弱受限" → 机检PASS，冷读能查出来
- **[23] 验证**器具禁令关键词，**但无法判断**"个人痕迹"是否合法
  - 写"拐杖上绑了布条"（可能是装饰也可能是防滑） → 机检PASS，需人工判断
- **[42] 验证**标点三禁的文本模式，**但无法判断**语境合法性
  - 对话标记错误时可能误判破折号

**结论**：机检约占60%验证覆盖，剩余40%需冷读+人工复核。

---

### Q2: gatecheck.py 报错说"枚举表不一致"怎么办？

**A**: [25] 检查发现账本的枚举表与脚本常量不匹配。

**修复方法**：
1. 打开 `templates/state-ledger.yaml`，找到末尾的 `枚举表` 数据块
2. 对比你的账本文件中的枚举表，看哪里不一样
3. 手动同步这些字段：
   - 辅具类型（腋拐/肘拐/平台拐/假肢及组合/无(单腿跳)）
   - 章节功能（主线推进/关系深化/日常样态/对抗危机/生存危机）
   - 主冲突线beat（推进/蓄势/留白）
   - 受限层级（核心/在场/余波/弱受限）

**为什么会不一致**：
- 账本被脚本整份重写过
- 技能库更新了枚举值但账本没同步
- 手动编辑账本时误删了枚举表块

### Q3: 运行 verify.py 或 gatecheck.py 失败怎么办？

**常见原因**：

**1. Python环境问题**
```bash
# 检查Python版本（需要3.6+）
python --version

# 安装依赖
pip install pyyaml
```

**2. 工作目录错误**
```bash
# 必须在技能库根目录运行
cd /path/to/novel-amputee-writing
python scripts/verify.py
```

**3. 项目目录结构不对**
```bash
# gatecheck.py 需要项目目录包含账本
python scripts/gatecheck.py /path/to/your-novel-project
```

**4. Windows编码问题**
- 症状：输出乱码或报 UnicodeDecodeError
- 解决：使用 `--report` 选项输出到文件
```bash
python scripts/gatecheck.py <dir> --chapter 1 --report report.txt
```

## 二、生理事实与类型

### Q4: 单侧髋离断和双侧髋离断的"空椅面"有什么区别？

**A**: **单侧可用"空椅面"，双侧不用**。

| | 单侧髋离断 | 双侧髋离断 |
|---|---|---|
| 臀部压住椅面吗 | ✅ 是（坐得实） | ✅ 是（坐得实） |
| "空"指什么 | **椅面前方没有腿伸出** | **两侧都没有腿** |
| 能用"空椅面"吗 | ✅ 能（因不对称对照） | ❌ 不能（因对称，无"另一边"） |
| 正确写法 | "那半边椅面空着" | "椅面前方整片空" |
| ❌ 错误写法 | "臀下悬空""没坐到椅子" | "空椅面""那半边空着" |

**关键**："空椅面"的张力来自**一边有一边没有的对比**，双侧对称就没有这个对比。

详见 `core/audience.md` 行115-127。

---

### Q5: 髋离断能不能跷二郎腿？

**A**: **不能**。

**原因**：髋离断无膝、无小腿，无法完成"患侧在上交叉"的动作。

**易混淆点**：
- ❌ 髋离断：不能跷二郎腿
- ❌ 膝上截肢：不能跷二郎腿
- ⚠️ 膝下截肢：**穿假肢时可以**（短时），**不穿不可以**

详见 `types/hip-disarticulation.md#不可能动作` 行214。

---

### Q6: 髋离断为什么日常不用假肢？

**A**: **能耗太高**（约为正常步行的2-3倍），且无股骨杠杆，步态机械。

**使用场景分层**：
| 场景 | 首选 | 原因 |
|------|------|------|
| 日常室内/短距离 | 双拐 | 省力、灵活 |
| 日常外出/长距离 | 双拐 | 假肢耗力大 |
| 正式场合/社交 | 假肢 | 外观需求 |
| 拍照 | 假肢 | 视觉呈现 |
| 需要腾手的工作 | 假肢+单拐 | 解放双手 |

**不是她"不够努力"**，是生物力学的客观限制。

详见 `types/hip-disarticulation.md#假肢使用差异`。

---

### Q7: 健腿单腿蹲是豁免吗？需要写"蹲姿受限"吗？

**A**: **健腿单腿蹲是正式豁免**，❌ **不写"蹲姿受限"**。

**正确写法**：
- 蹲下/起身须**一手支撑**（扶拐/扶墙/扶健侧膝/撑地）
- 蹲姿做事：一只手撑地或扶物，**另一只手可做简单的事**
- 起身三种写法：扶拐撑起 / 撑扶健侧膝盖 / 就手扶旁边的东西

**❌ 错误写法**：
- "她无法蹲下"
- "蹲姿对她来说极难"
- "蹲姿受限"

**例外**：无扶手深蹲（蹲坑、蹲式便器）确实难 - 可蹲但起不来，须有可扶之物。

详见 `types/hip-disarticulation.md#日常动作差异` 行97-108。

## 三、移动与辅具

### Q8: "单腿跳"和"拄拐走"什么时候用哪个？

**A**: **默认用辅具**。单腿跳只在特殊情况下使用。

**铁则**：
- 拐杖在手 = 拄拐走（写出步态：摆至步/摆过步）
- 穿着假肢 = 假肢走
- ❌ 不得写辅具与角色分离（严重错误第3类）

**单腿跳仅限四种情形**：
1. **临时无辅具**：被夺/来不及捡/放下去做事（须过腾手门槛）
2. **无辅具设定**：角色设定就是不用辅具
3. **辅具空白期**：移动辅具全部不可用的跨章状态
4. **特殊移动在位**：翅膀/御剑/超级跳等能力承担移动时

**易错**：开篇/出场直接写单腿跳，但没交代辅具在哪 = 分离错误。

详见 `topics/mobility-modes.md#一、移动方式分层`。

---

### Q9: 角色可以"连续跳几十次"吗？

**A**: **可以**。

**多年档**：可稳定连跳几十次（身体已适应）

**近期档**：幻肢感触发按 `topics/timeline.md` 档位总表，不按步数安排失衡、停顿或摔倒。

详见 `topics/mobility-modes.md#二、体力节奏`。

---

### Q10: 拐杖被打飞后，她怎么移动？

**A**: **单腿跳**（临时无辅具）。

**处置链**：
1. 够到拐杖的位置
2. 单腿跳过去
3. 捡回（可能需要蹲下）
4. 重新撑起

**或者**：就地放弃，单腿跳着继续战斗/周旋（如果拐杖被踢得太远）

**不能写**：拐杖自动回到手上 / 她突然正常走路了

详见 `topics/limitation-scenes.md#衍生类1：辅助器具剥夺`。

## 四、器具与禁令

### Q11: 器具禁令到底禁什么？"个人痕迹"算不算？

**A**: 禁**损耗、更换、送修、议论**，允许**个人痕迹**。

**❌ 绝对禁止**：
- 拐头/杖尖磨损、磨薄、磨亮、包浆
- 换拐头、换胶垫、配一副新的
- 假肢内衬/关节送修更换
- 残肢袜磨破换新
- "该换一副了""送修""买备用"等台词与独白

**✅ 合法的个人痕迹（四类）**：
1. **体温/汗渍痕迹**：持握位置被焐深、接受腔内侧压痕
2. **主动改造/标记**：刻字、绑布条（对齐标记）、贴纸
3. **使用习惯痕迹**：某个角度的磨损（因她的步态）
4. **情感载体**：某人送的、某次经历留下的（来历，不是损耗）

**例外（三种情况允许）**：
1. **外力当场破坏**：打断、踩碎、当场损坏
2. **有即时事由的功能性处理**：当场绑紧、临时修补（不是日常维护）
3. **非损耗的个人痕迹**：见上述四类

详见 `core/audience.md#★器具损耗与更换禁令`。

---

### Q12: 为什么禁止写器具损耗？

**A**: 三个原因：

1. **避免滑向"器具维护流水账"**：关注点应在人物与受限，不是物品保养
2. **符合devotee偏好**：受众关注身体与能力，不关注器具细节
3. **保持叙事焦点**：写器具怎么旧了，会让"器具"成为主角

**替代写法（要"器物有分量"）**：
- 写**来历**（当年自己挑的、比过三副）
- 写**使用习惯**（只有她握得出那个位置）
- 写**个人痕迹**（手柄被焐深）
- 写**器具在场景里的戏份**（拐杖勾衣架、够灯开关）

## 五、写作流程与机制

### Q13: 为什么改了 gatecheck.py 后要重算哈希基线？

**A**: 因为 **[5] 检查会验证 gatecheck.py 的哈希值**，改动脚本 = 篡改验证机制。

**重算方法**：
```bash
python scripts/selfcheck.py --update-baseline
```

**然后运行**：
```bash
python scripts/verify.py
```

**原因**：gatecheck.py 是交付闸的核心，改它 = 改验证规则。如果不更新哈希，会被 selfcheck [5] 检测为"脚本被篡改" → FAIL。

详见 `MAINTENANCE.md#四、改动流程` 第3步。

---

### Q14: 什么是"压缩恢复协议"？什么时候触发？

**A**: 小上下文模型在**第一章成文前很可能压缩一次甚至多次**。

**触发自检**："能引用hard-layer禁令原文吗？"不能 = 疑似被压缩。

**最小恢复集（5件）**：
1. `rules/hard-layer.md` 全文
2. 项目目录 `chapter-rules-N.md`（本章规则包）
3. 项目目录 `chapter-contract-N.md`（本章写作卡）
4. 账本关键块（声音卡+文风契约+意象母题）
5. 上一章末尾约500字

**恢复后留痕**：压缩发生 = 可审计事件，需记录。

详见 `SKILL.md#二、压缩恢复协议`。

---

### Q15: flash / pro / max 三种模式有什么区别？

**A**: 分工方式不同，质量闸相同。

| 模式 | 分工 | 速度 | 适用 |
|------|------|------|------|
| **flash** | 自写自审（单代理） | 快 | 时间紧/试写 |
| **pro** | 一写一审（主代理写+独立冷读） | 中 | 默认推荐 |
| **max** | 队长+队员（队长统筹不写正文） | 慢 | 高质量要求 |

**共同点**：全部通过同样的质量闸（大纲质量闸/章六要素/严重错误五项合一闸/章末核查清单）

**选择时机**：收集流程末题选择；选定后全书锁定。

详见 `core/workflow.md#〇、工作流模式`。

## 六、内容与创作

### Q16: 什么是"核心受限" vs "弱受限"？怎么判断？

**A**: 看**行为方式**是否须改变。

| | 核心受限 | 弱受限 |
|---|---|---|
| **定义** | 行为方式须改变 或 无解 | 行为方式不变 但有代价 |
| **例子** | 够不着高处→换个够法/放弃 | 走长路累了→歇一下继续 |
| **受众** | ✅ 受众爱看（"能不能"） | 只能做背景 |
| **登记** | 占核心beat配额 | 不占配额，不登记 |
| **写法** | 可重点描写 | 点到即止 |

**判定三问**（见Q4）：
1. 办成了吗？
2. 换健全人也难吗？
3. 难在缺腿/手吗？

三问全过 → 再判层级（核心/弱受限/点缀）

详见 `topics/limitation-scenes.md#六、受限层级判定`。

---

### Q17: "空椅面""空鞋""空袖管"有什么区别？

**A**: 按类型取象，不可混写。

| 类型 | 取象 | 说明 |
|------|------|------|
| **单侧髋离断** | 空椅面、空鞋、裆线以下的空 | 因不对称对照 |
| **双侧髋离断** | ❌ 不取"空椅面"；取"裆线以下的空""两条空裤管" | 对称，无"另一边" |
| **膝上/膝下** | 残端下缘以下的空裤管（仅未处理时） | 已裁剪则无 |
| **肩离断** | 空袖管 | |

**核心口径**："空"的张力来自**在/不在的对比**或**期待落空**。

详见 `core/audience.md` 行111-129。

---

### Q18: 峰值段到底应该在哪里？怎么算位置？

**A**: **位置在65-85%之间**（接近章末但后面留收束），**占全章15-25%**。

**计算方法**：
- **分母** = 全章总字数（非空白字符）
- **位置** = 峰值段**起点**在全章的百分比
- **示例**：3000字的章，峰值段从第2000字开始 → 位置 = 66.7%（✅ 在65-85%内）

**边界情况**：
- **单场景章**：峰值段可以占全章60%以上，位置放宽为 ≥50%
- **短篇（≤3000字）**：位置放宽为 ≥60%

详见 `core/intensity.md#一、强度曲线`。

## 七、错误与调试

### Q19: gatecheck 报"章号不连续"怎么办？

**A**: [2] 检查要求章号集合 == {1..N}。

**常见原因**：
- 跳号写作（写完第1章直接写第3章）
- 章号类型混淆（有的用数字、有的用字符串）
- 删除了中间某章但没更新账本

**修复**：
1. 检查账本 `工作流执行日志` 块，看缺哪个章号
2. 补上缺失的章，或重新编号
3. 章号一律用整数（int），不用字符串

---

### Q20: 冷读报告说"同源判定≥95%"是什么意思？

**A**: [13] 检查发现审查报告与自查报告的判定**过于一致**。

**什么是同源**：审查员的22维判定向量与自查折算的判定向量，一致比例≥95%。

**为什么是WARN不是FAIL**：
- 合法同判（引文/位置不同）是允许的
- 硬防伪由 [8] 输入隔离 / [11] 引文实证 / [12] 主语纯净兜底
- 主代理需要复核：是真的同判，还是复制粘贴？

**处理流程**（见 `core/workflow.md#冷读报告受理验收流程`）：
1. 检查引文是否来自草稿原文
2. 检查主语是否纯净（没有"我写""作为队长"）
3. 人工读一遍，判定是否真的一致
4. 合法同判 → 接受；伪装同源 → 退回重审

### Q22: 如何向技能库报告bug或建议？

**A**: 本技能库遵循"维护期例外"原则（SKILL.md#三、严重错误分级）。

**报告渠道**：
1. GitHub Issues（如果有公开仓库）
2. 直接修改本地副本，运行 `verify.py` 验证
3. 联系维护者（见 README.md）

**报告内容应包含**：
- 问题描述（具体什么不对）
- 复现步骤（如何触发）
